Camada / Subcamada Responsabilidade no Projeto Anti-Pattern Evitado
View Renderizar telas responsivas e capturar interações do usuário. Não acessa banco de dados nem calcula totais/regras de negócio.
Controller Mapear rotas HTTP, validar DTOs (@Valid) e delegar ao Service. Sem SQL/JPQL, sem EntityManager e sem regra de negócio (God Controller).
Model → Service Orquestrar casos de uso, transações e publicar eventos Observer. Não importa pacotes de View/HTTP nem depende de detalhes de UI.
Model → Repository Executar operações CRUD e consultas tipadas via Spring Data JPA. Não contém regras de negócio nem dispara notificações.
Model → Entity Representar estado e relacionamentos do domínio com mapeamento JPA. Não chama Services nem executa persistência própria (sem Active Record).
MVC • Camada View

Camada View: Templates Thymeleaf e Assets Estáticos

Localizada em src/main/resources/templates/ e src/main/resources/static/

📄 Templates Thymeleaf (templates/)

  • Fragments reutilizáveis (layout/): header.html e footer.html padronizam cabeçalho e rodapé.
  • Totem (totem/index.html): Recebe do Controller categorias, produtos e tipoConsumo via Model do Spring MVC.
  • Cozinha (kds/index.html): Renderiza a fila de preparo por status.
  • Salão (senhas/index.html): Exibe senhas em preparo e prontas.
  • Admin (admin/index.html): Painel de gestão de cardápio, estoque e relatórios.

🎨 Estáticos & Interatividade (static/)

  • Estilos (static/css/): Layout responsivo com CSS moderno e variáveis customizadas.
  • Scripts (static/js/): totem.js, kds.js, painel-senhas.js e admin.js consomem as APIs REST via fetch para atualização dinâmica sem acoplamento ao banco.
  • Mídia (static/img/): Logotipo e ilustrações SVG dos produtos (burger-hero.svg, fries.svg, drink.svg, etc.).
Separação estrita: O JavaScript da View apenas envia DTOs JSON e exibe o resultado validado e calculado pelo servidor.

@Controller
public class TotemViewController {
    private final CategoriaService categoriaService;
    private final ProdutoService produtoService;

    @GetMapping("/totem")
    public String totem(Model model, HttpSession session) {
        carregarDadosCardapio(model, session);
        return "totem/index"; // View Thymeleaf
    }

    private void carregarDadosCardapio(Model model, HttpSession s) {
        model.addAttribute("categorias", categoriaService.buscarAtivas());
        model.addAttribute("produtos", produtoService.buscarAtivos());
    }
}
Proteção por DTOs: Os controllers recebem DTOs (dto/request/) com Bean Validation (@Valid) e retornam DTOs higienizados (dto/response/), nunca expondo entidades JPA diretamente. Erros são tratados globalmente pelo GlobalExceptionHandler.
MVC • Camada Model

Subcamadas do Model: Service, Entity e Repository

Pacote com.restaurante.pdv.model dividido em 3 responsabilidades independentes

🧠 Service (model.service)

Centraliza regras de negócio, cálculos monetários com BigDecimal, transações (@Transactional) e eventos.

  • PedidoService: Valida estoque, calcula subtotais, gera senha e publica eventos.
  • ProdutoService: CRUD e controle de estoque.
  • PagamentoService & PixEmvService: Processamento de pagamentos e payload PIX.
  • RelatorioService: Fechamento de caixa.
  • SenhaSequencialService: Senha diária thread-safe.

📦 Entity (model.entity)

Objetos de domínio puro mapeados para o banco relacional via JPA.

  • Categoria & Produto
  • OpcaoAdicional (customização)
  • Pedido, ItemPedido, ItemPedidoOpcao
  • CobrancaPix
  • Enums: StatusPedido, FormaPagamento, TipoConsumo, TipoOpcao

🗄️ Repository (model.repository)

Interfaces de acesso a dados estendendo JpaRepository<T, ID>.

  • ProdutoRepository
  • PedidoRepository
  • CategoriaRepository
  • OpcaoAdicionalRepository
  • ItemPedidoRepository
  • CobrancaPixRepository
Benefício da Decomposição: Alterar uma regra de cálculo de combo impacta apenas o Service; alterar um índice ou consulta SQL impacta apenas o Repository; alterar atributos de domínio fica isolado na Entity.
Padrão de Projeto

Padrão Repository na Prática

Abstração da camada de persistência com Spring Data JPA e Inversão de Dependência (DIP)

🎯 Por que e onde foi utilizado?

  • Os Services (ex: PedidoService, ProdutoService) dependem apenas de interfaces (PedidoRepository, ProdutoRepository), nunca de JDBC ou EntityManager direto.
  • O Spring Data JPA gera em tempo de execução as implementações CRUD (save, findById, delete).
  • Derived Queries: Métodos cujo nome gera SQL automaticamente (findByCategoriaIdAndAtivoTrue).
  • Consultas JPQL (@Query): Agregações analíticas e relatórios em PedidoRepository.
@Repository
public interface ProdutoRepository extends JpaRepository<Produto, Long> {
    List<Produto> findByAtivoTrue();
    List<Produto> findByCategoriaIdAndAtivoTrue(Long categoriaId);
    boolean existsByNomeIgnoreCase(String nome);
}

@Repository
public interface PedidoRepository extends JpaRepository<Pedido, Long> {
    List<Pedido> findByStatusInOrderByDataHoraAsc(Collection<StatusPedido> s);

    @Query("SELECT COUNT(p), COALESCE(SUM(p.valorTotal), 0) FROM Pedido p " +
           "WHERE p.pago = true AND p.dataHora >= :inicio AND p.dataHora <= :fim")
    List<Object[]> somarFaturamentoEPedidosPorPeriodo(
            @Param("inicio") LocalDateTime inicio,
            @Param("fim") LocalDateTime fim);
}

Persistência de Dados

JPA e ORM (Hibernate) no Mapeamento Relacional

Como objetos Java viram tabelas relacionais com integridade transacional e concorrência otimista

@Entity
@Table(name = "produtos", indexes = {
    @Index(name = "idx_produto_categoria", columnList = "categoria_id")
})
public class Produto implements Serializable {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Column(nullable = false, precision = 10, scale = 2)
    private BigDecimal preco;

    @Version // Concorrência Otimista contra race conditions
    private Long version;

    @ManyToOne(fetch = FetchType.LAZY)
    @JoinColumn(name = "categoria_id", nullable = false)
    private Categoria categoria;
}

🔧 Papéis na Persistência

  • JPA (Especificação): Define o contrato padrão (jakarta.persistence.*) com @Entity, @Table, @ManyToOne, @ManyToMany e @Version.
  • Hibernate (ORM): Motor que gera o DDL e traduz objetos Java para SQL no H2 (dev) ou PostgreSQL (prod).
  • Configuração (application-dev.yml): ddl-auto: update, show-sql: true, open-in-view: false (evita lazy-loading na View).
  • Concorrência Otimista (@Version): Garante que duas compras simultâneas do último item em estoque não gerem saldo negativo.
  • Atomicidade (@Transactional): Em PedidoService, criação do pedido + itens + baixa de estoque ocorrem em transação única.
